SMEP: Secure Messaging Envelope Protocol, Version 1

1. Overview
===========

SMEP encrypts a message from one X25519 identity to another and packs it
into a self-contained binary envelope.

    X25519        RFC 7748
    SHA-256       FIPS 180-4
    AES-256-GCM   NIST SP 800-38D

All integers are big-endian. Keys, IVs, ciphertext and tags are
opaque bytes, written as-is.


2. Identities
=============

Private key: 32 random bytes from a CSPRNG, clamped per RFC 7748:

    k[0]  &= 248
    k[31] &= 127
    k[31] |= 64

Clamping is idempotent, so a stored key may be clamped or not.

Public key: X25519(private_key, 9), the 32-byte RFC 7748 encoding.
The public key is the identity's address.


3. Encryption
=============

    shared = X25519(sender_private_key, recipient_public_key)
    key    = SHA256(shared)
    iv     = 12 random bytes
    aad    = header, bytes 0-77 of the envelope (section 4)
    ciphertext || tag = AES-256-GCM(key, iv, plaintext, aad)

The tag is 16 bytes. If shared is all zero bytes, the operation MUST
fail.

The header is complete before encryption: payload_size is
28 + len(plaintext), since the ciphertext is as long as the plaintext.
The header bytes are serialized once and used both as the aad and as
the start of the envelope.

The key is the same in both directions, so either party can decrypt. To
decrypt, compute shared with the local private key and the peer's public
key. The peer is sender_public_key, or recipient_public_key if the local
identity is the sender (decrypting one's own sent envelope). The aad is
the received header bytes as-is, not re-serialized from parsed fields.
If the tag does not verify, the envelope MUST be rejected.

Plaintext is UTF-8 text when content_type is 0x01, otherwise raw bytes.


4. Envelope Format
==================

    offset  size  field                  type
    ------  ----  ---------------------  -------------------------------
    0       1     version                uint8, 0x01
    1       32    sender_public_key      X25519 public key
    33      32    recipient_public_key   X25519 public key
    65      8     timestamp              uint64, Unix seconds, sender clock
    73      1     content_type           uint8, see section 5
    74      4     payload_size           uint32, = 12 + len(ciphertext) + 16
    78      12    iv
    90      n     ciphertext             n = payload_size - 28
    90+n    16    tag

The header is 78 bytes. The total length MUST equal 78 + payload_size
and MUST NOT exceed 4 MiB (4,194,304 bytes), so payload_size is at most
4,194,226 and the plaintext at most 4,194,198 bytes.

A writer MUST refuse to create a larger envelope. A parser MUST reject
an envelope with a version other than 0x01, a payload_size below 28, a
total length that does not match, or a total length above 4 MiB.


5. Content Types
================

    0x01  TEXT_UTF8
    0x02  IMAGE
    0x03  VIDEO
    0x04  AUDIO
    0x05  FILE
    0xFF  UNKNOWN

content_type is a display hint only. It is authenticated as part of
the header but does not otherwise affect cryptography.
The envelope carries no filename or MIME type.


6. Envelope Hash
================

    hash = SHA256(envelope)

over the complete envelope bytes, header and body. The hash is not
carried in the envelope: whoever holds the bytes computes it. Copies
of one envelope are byte-identical and share a hash; any other envelope
has a different one, since the iv is random. Use the hash, never a header
field, to recognize an envelope already seen.


7. Security Notes
=================

- The header is authenticated as aad, so no header field can be altered
  without the tag failing. The two public keys are also bound by the
  key itself. A valid tag does not make the timestamp true: it is
  whatever the sender's clock said.
- A valid tag proves the envelope was made by the holder of the sender's
  or the recipient's private key.
- Every envelope between the same two identities uses the same key, so
  IVs MUST be random and never reused.
- No forward secrecy, no replay protection. Senders, recipients,
  timestamps and sizes are visible to anyone holding the envelope.
